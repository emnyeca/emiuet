# Sonatino / Emiuet 比較技術レポート

作成日: 2026-08-26  
対象: Sonatino `3dd28dbe` / Emiuet `6cb9148b`

## 1. 結論

Sonatino は、Emiuet の完成形を直接示す設計ではない。Sonatino は小型の ESP32-S3 オーディオ開発ボードであり、Emiuet はギタリスト向けの大型 MIDI 演奏装置である。中心となるユーザー体験も、主要な信号も、基板形状も大きく異なる。

一方で、次の領域はEmiuetにとって有用な参照になる。

1. ESP32-S3、USB-C、Li-ion電源を同居させる際の回路ブロック構成
2. デジタル系とアナログ系の電源・GND・デカップリングの考え方
3. USB、電源、MCU、外部I/Oを小さな領域へまとめる部品配置
4. 起動・リセット・ストラッピング・テストポイントの扱い
5. 回路図上に計算根拠、設計意図、DNP候補を残す記述方法
6. 部品の供給終了やライセンスを設計リスクとして明示する姿勢

最も重要なのは、Sonatino の回路を移植することではなく、**Emiuet の制御基板領域をレビューするための比較基準として使うこと**である。

Emiuet は、電源の目的適合性、USBの役割分離、演奏入力、MIDIファームウェア、製造出力の点では、すでにSonatinoよりEmiuetの目的に合った固有設計を持つ。ここをSonatinoへ寄せるべきではない。

## 3. 製品としての主従関係

| 観点 | Sonatino | Emiuet |
|---|---|---|
| 主目的 | ESP32-S3による音声処理・開発 | ギタリスト向け演奏用MIDIコントローラー |
| 中心体験 | 音声入出力とDSP実験 | 6弦×13フレット、コード、弦単位表現 |
| 製品性格 | 汎用開発ボード | 意図的に制約された楽器 |
| 主要入力 | マイク、ライン、microSD、GPIO | 78キー、3スライダー、3ボタン |
| 主要出力 | ライン、ヘッドホン、スピーカー、GPIO | USB-MIDI、TRS MIDI、BLE-MIDI |
| UI | 最小限のボタン、LED、DIP | OLED、状態LED、演奏モード操作 |

この違いから、Sonatino のオーディオ回路や拡張ヘッダーをEmiuetへ追加することは、参考利用ではなく製品目的の変更になる。参照範囲は共通基盤技術に限定すべきである。

## 4. ハードウェア比較

### 4.1 全体仕様

| 項目 | Sonatino | Emiuet | 評価 |
|---|---|---|---|
| MCU | ESP32-S3-WROOM-1U、16MB Flash、8MB PSRAM | ESP32-S3-MINI-1 | 同じMCU系列だがモジュールと要求が異なる |
| 無線 | Wi-Fi、BLE 5.0 LE | BLE-MIDIおよび専用アプリ接続を計画 | 無線機能は共通、用途は異なる |
| USB | USB-C 1ポート、給電・プログラム・USBデータ | 充電専用と固定USB Device/UFPの2ポート | Emiuetの役割分離を維持すべき |
| 電池 | 1セル、TP4056とディスクリート回路 | 1セル、BQ24074 power-path | Emiuetの方が演奏中給電の目的に適合 |
| 3.3V | デジタル用とAVDD用にNCP167を分離 | AP7333とアナログ配慮、別途5V昇圧 | Sonatinoの電源分離はレビュー材料になる |
| USB保護 | SRV05-4、CCのRd | Rev.AはTPD2EUSB30、コモンモードチョーク、ヒューズ、TUSB320 | Rev.Bでは固定UFP化して役割回路を簡略化する |
| 基板層 | 4層 | 2層 | 直接模倣不可。信号帰路の比較基準になる |
| 外形 | 約65×30mm | 約297×102.4mm | 配線密度とコスト条件が大きく異なる |
| 板厚・表面 | 1.6mm、ENIG | 1.6mm、ENIG | 共通 |
| GND | GND/GNDA、0Ω接続点あり | GNDD/GNDA | 接続位置と帰路の再確認が重要 |
| 製造データ | KiCadソース中心 | BOM、座標、IPC netlist、製造ZIPあり | Emiuetの方が製造引き渡しに近い |

### 4.2 MCU、起動、書き込み

共通点はESP32-S3とネイティブUSB D-/D+の利用である。SonatinoではESP32-S3-WROOM-1Uを使い、BOOTボタン、RESETボタン、ENのRC、MCLKテストポイントを回路図上で明確に区切っている。GPIO0が起動時ストラッピング対象であることも注記されている。

EmiuetではGPIO45/GPIO46をキーマトリクス列に使うため、起動後300ms待機し、行入力、列出力の順に有効化し、さらに初回5スキャンを破棄する実装がある。この処理はEmiuet固有の起動安全策であり、Sonatinoより踏み込んでいる。

Emiuetに活かせる点は次の通り。

- 回路図上でBOOT、RESET、EN、書き込み経路を一つのブロックとして見せる
- 起動時に影響する信号へ、回路図上の注記とファームウェア上の保護を両方置く
- GND、EN/RESET、BOOT、3.3V、5V、USB D+/D-へ、プローブしやすいテストポイントを用意する

EmiuetにはTP1/TP3/TP4/TP5があるが、製造BOM・座標データでは通常部品として現れない。これはSMDテストパッドであれば正常だが、基板レビュー時には各TPのネット名と実機でのアクセス方向を明示したテスト表が必要である。

### 4.3 USB-C

SonatinoのUSB-Cは、5.1kΩのCC抵抗を持つシンプルなUSBデバイス/シンク構成である。単一ポートでプログラミング、通信、給電を兼ねるため、回路の見通しがよい。

この比較を作成した時点のRev.Aでは、充電専用ポートとUSB-MIDI/DRP
ポートを分け、TUSB320で役割を扱う前提だった。このDRP/OTG前提は
Rev.Bの正式仕様では廃止された。Rev.Bは充電専用USB-C #1と、固定USB
Device/UFPのUSB-C #2を分離したまま、CC1/CC2をRdで固定する。

ESD、必要な信号フィルタ、VBUS保護・検出はUSB roleとは別の安全要件
なので維持または実測評価する。

Sonatinoから取り込む価値があるのは、USBセクションを回路図上で独立させ、CC、VBUS、D+/D-、ESD、電源切替の関係を一画面で追える構成である。

Emiuetでは次を次回基板前に確認するべきである。

1. USB-MIDI側D+/D-の差動ペアが、層変更やGND分断をまたがず連続した帰路を持つこと
2. ESD素子、コモンモードチョーク、MCUの順序と距離
3. 2ポート間のVBUS逆流防止と、片側または両側を同時接続した状態
4. 固定UFPのCC抵抗と、自己給電Device用VBUS検出の対応
5. ネイティブUSBとUSB-Serial/JTAGを混同しない書き込み・検証手順

### 4.4 電源、充電、バッテリー

SonatinoはTP4056、MOSFET、ダイオード、DW01系保護を組み合わせた比較的単純な1セル電源である。回路図には逆漏れへの対策、充電電流、逆極性保護、バッテリー分圧の計算が直接記載されている。バッテリー最大4.2Vを約3.18Vへ落とし、分圧損失を約6.8µAとする説明もある。

Rev.AのEmiuetはBQ24074によるpower-path、TPS61023による5V生成、AP7333による3.3V生成に加え、LM66100で内部5VをUSB-C #2 VBUSへ送る経路を持つ。Rev.Bでは前者の製品電源要件を維持して検証する一方、Device-only方針によりLM66100のUSB-C #2出力経路は削除対象である。Host用経路と「演奏しながら充電する」ための内部power-pathを同一視してはならない。

したがって、SonatinoのTP4056電源回路への置換は推奨しない。取り込むべきなのは次の設計表現である。

- 分圧比、待機電流、充電電流、電圧上限を回路図の近くに書く
- USBのみ、電池のみ、両方接続、電源OFFの各電流経路をレビューする
- 逆接、逆流、保護IC動作時の状態を明示する
- 重要な電源レールへテストポイントを置く

Emiuetの回路データでは、TPS61023のシンボルメタデータに明確な不整合がある。値は`TPS61023DRLR`だが、DatasheetがTPS62A02を指し、Descriptionも降圧コンバーターになっている。実回路の部品値、ピン番号、フットプリントが正しくても、レビュー時に誤判断を誘発するため修正対象である。

### 4.5 アナログ、GND、ノイズ

SonatinoはADC、DAC、マイクプリアンプ、ヘッドホンアンプ、スピーカーアンプを持つため、アナログ品質への要求が高い。AVDD専用LDO、GNDA、フェライトビーズ、ローパスフィルター、各IC直近のデカップリングが設計の中心にある。GNDとGNDAはR33の0Ωで接続され、接続位置を回路として明示している。

Emiuetには音声回路はないが、3本のスライダーとBAT_VSENSEがある。これらは演奏表現に直結するため、分解能より再現性とノイズ耐性が重要である。

Emiuetへの適用方針は次の通り。

- SonatinoのAVDD専用LDOをそのまま追加するのではなく、まず現在のRC、デカップリング、GNDA/GNDD接続、ADCサンプリングを測定する
- 昇圧回路、LED/PWM、キーマトリクス列、USB D+/D-からADC配線を離す
- GNDA/GNDDを分ける場合、信号の帰路が分断を横断しないことを確認する
- スライダー端、MCU ADC端、BAT_VSENSEでノイズと応答を測り、ハードウェアRCとファームウェアEMAの役割を分ける

SonatinoのGND分割は参考になるが、分割そのものが正解ではない。2層で横長のEmiuetでは、分割面が高速信号や入力線の帰路を切る危険があるため、接続点と電流経路で判断する必要がある。

### 4.6 PCB構成と実装密度

Sonatinoは約65×30mmの4層基板で、信号層2層と内層電源2層を持つ。部品はコネクタの周辺とMCU/音声ICの近傍に密集し、四隅に固定穴を置く。小さな混載基板として、電源帰路、デカップリング、USB差動配線、音声クロック配線をまとめやすい構成である。

Emiuetは約297×102.4mmの2層基板であり、大部分は78キーの規則的なマトリクスである。電子回路は端部に集約され、別のトップ左右基板とプレート基板も持つ。この構造は楽器の形状と演奏性から生じており、Sonatinoの小型化を目標にすべきではない。

活用方法は以下が妥当である。

- Emiuet全体を4層化するのではなく、USB・電源・MCUが集まる領域の配置と帰路をSonatino並みの密度でレビューする
- 2層でUSB、昇圧、ADCの共存が難しいことが測定で判明した場合に限り、4層化または制御部の小基板化を比較案にする
- キーマトリクス領域はEmiuet固有の低速・大面積設計として扱い、高速/アナログ領域とレビュー基準を分ける

## 5. ファームウェアと機能実装

### 5.1 Sonatino側

今回クローンしたSonatinoリポジトリにはファームウェアがない。READMEから別のExamplesリポジトリへ案内されるが、本比較の対象には含めていない。そのため、リアルタイム処理、USB、BLE、電源状態管理について、Sonatinoをファームウェア実装の参照にはできない。

### 5.2 Emiuet側

Emiuetには次の実装がある。

- 6×13キーマトリクスの走査とデバウンス
- ストラッピングピン保護の遅延初期化
- ノート生成と弦単位チャンネル割り当て
- 上方向専用ピッチベンドとStringwise Bend
- USB-MIDIのTinyUSB実装
- TRS MIDIの31250bps UART実装
- USB/TRS/BLEごとの非同期キュー
- Pitch BendとCC#1のチャンネル別coalescing
- ADC管理、スライダー平滑化、OLED、LED、電源状態表示

これはSonatinoにはない、Emiuetの中核的な資産である。

ただし、実装済みと設計済みを分ける必要がある。

| 項目 | 状態 |
|---|---|
| USB-MIDI | 実装あり。実機でのネイティブUSB列挙確認が残る |
| TRS MIDI | 実装あり。UART0コンソール競合を避ける設定が必要 |
| BLE-MIDI | キュー形状のみ。低レベル送信は成功扱いするstub |
| BLEペアリング | weak stub |
| Telemetry/Control/OTA | 仕様文書あり。実装は確認できない |
| OLED | 実装あり。ただし関数名やログに`demo`が残る |
| 自動テスト | Emiuet固有のテスト群は確認できない |

ファームウェアに関する優先課題は、Sonatinoからコードを借りることではなく、現在の実装状態を人間が誤認しない形にすることである。

- `firmware/README.md`がESP-IDFのHello Worldテンプレートのままなので、実際のビルド、書き込み、設定、検証手順へ更新する
- BLEを「設計済み」と「実装済み」に分け、stubを通常ルートで有効にしない
- `oled_demo_start()`など、製品機能になったdemo命名を整理する
- USB列挙、TRS送信、キーマトリクス、ピッチベンド復帰を保護する最小限の試験を置く

なお、`board_pins.h`のADCコメントはGPIO1/2のチャンネル番号を実装値より1つ大きく説明している一方、マクロはGPIO1→CH0、GPIO2→CH1、GPIO4→CH3になっている。実装とコメントのどちらを正とするかではなく、ESP32-S3のデータシートとESP-IDF定義で再確認し、コメントを一致させるべきである。

## 6. 文書、ライセンス、保守性

SonatinoはCERN-OHL-P-2.0を明示し、OSHWA認証番号、商標、文書の扱い、WM8782の供給終了をREADMEで説明している。設計の再利用可能性と、再利用してはいけない名称・文書の境界が比較的明確である。

Emiuetは設計思想、禁止事項、音楽的な判断をSonatinoより詳しく記録している。一方で、ライセンスは未決定である。

Sonatinoの回路断片をEmiuetへ実際に移植する場合は、少なくとも次を行う必要がある。

- コピー元、対象回路、取得コミット、変更内容、変更日を記録する
- Sonatinoの名称やロゴをEmiuetの製品表示へ流用しない
- CERN-OHL-PのNotice要件を確認し、必要な表示を保持する
- Emiuet自身のハードウェア/ファームウェア/文書ライセンスを公開前に決める

これは法的助言ではない。公開・販売前には採用部分と配布形態に応じた最終確認が必要である。

## 7. Emiuetへ活かす優先順位

### 優先度A: 次回PCB製造前

1. **U1のモジュール/フットプリント照合**  
   BOM上の値はESP32-S3-MINI-1だが、フットプリント名は`ESP32-S2-MINI-1_thermalVia_noSilk`である。名称だけの流用か、実パッドも互換前提かを、公式推奨ランドパターンと照合する。

2. **TPS61023シンボルメタデータ修正**  
   誤ったデータシートと降圧説明を修正し、ピン番号、FB抵抗、インダクタ、出力コンデンサも正本データシートで確認する。

3. **USB-C 2ポートの状態表を作る**  
   電池のみ、充電USBのみ、MIDI USBのみ、両USB同時、電源OFFを行列化し、VBUS、SYS、5V、3.3V、逆流、列挙動作を確認する。

4. **GNDA/GNDDと高速信号帰路を確認する**  
   USB差動対、ADC入力、昇圧スイッチング電流、MIDI電流ループがGND境界を不適切に横断していないか確認する。

5. **ERC/DRC結果を製造スナップショットへ残す**  
   現在の製造ZIP、BOM、座標に加え、製造対象コミットに対応するERC/DRCの結果を保存する。

6. **実機測定項目を固定する**  
   USB切替時のリセット、3.3V/5V立上り、ADCノイズ、低電圧時動作、GPIO45/46押下起動、USB列挙、TRS MIDI波形を測る。

### 優先度B: 人間が監修しやすい設計へ

1. 回路図を、全体、USB/電源、MCU/UI、キーマトリクス程度の少数の階層へ整理する
2. 分圧、充電電流、昇圧出力、RC時定数を回路の近くへ記載する
3. テストポイント一覧をネット名、目的、正常値とともに1表へまとめる
4. BOMへ供給リスク、代替可否、正本データシートを持たせる
5. `firmware/README.md`を実装に一致させる
6. Sonatinoを実際に引用した場合だけ、第三者Noticeを追加する

### 優先度C: 測定結果が必要な選択肢

- 制御部だけの4層化または小基板化
- ADC用の独立アナログ電源
- USB/電源回路の追加シールドやフィルタ
- テスト治具用パッドの増設

これらはSonatinoに存在するという理由だけでは採用せず、Emiuet試作機のノイズ、EMI、実装歩留まり、コストから判断する。

## 8. 直接流用しないもの

- WM8524、WM8782、MAX98357A、TPA6132A2、MAX4467などの音声回路
- TRRSオーディオジャックとmicroSD
- 汎用GPIOヘッダー
- TP4056中心の充電構成
- 単一USB-Cポートへの統合
- WROOM-1Uへの変更
- Bluetooth Audio EditionのA2DP構成
- 4層基板という結論そのもの

これらはSonatinoの目的には合理的だが、Emiuetの楽器としての主目的、薄型化、既存のpower-path方針、MIDI出力方針を弱める。

## 9. EmiuetがSonatinoより先に進んでいる点

- 演奏中の安定性を明文化したpower-path方針
- 充電とUSB-MIDIの物理ポート分離
- 78キーの実楽器入力とMPE風の弦単位表現
- MIDI生成をI/Oから分離する非ブロッキング構造
- USB/TRS/BLEごとのキューと連続値coalescing
- ストラッピングピンを考慮した段階的初期化
- BOM、座標、IPC netlist、製造ZIPの保持
- 製品固有の判断と禁止事項を残した文書

したがって、比較の目的はEmiuetをSonatinoへ近づけることではない。Sonatinoの成熟した小型混載基板の作法を使って、Emiuet固有設計の弱点を早く見つけることである。

## 10. 最終評価

Sonatinoから最も価値高く得られるものは、オーディオ機能ではなく、**小型ESP32-S3混載基板における電源・USB・GND・デカップリング・テスト性の見せ方**である。

Emiuetは目的、入力方式、MIDI処理、電源要求の面で独自性が強く、主要アーキテクチャを変更する必要はない。特に電源はEmiuet内部に保持し、HearthやEUB-BUSを通常動作の前提にしない。次回基板前には、Sonatinoを比較基準として、U1フットプリント、TPS61023メタデータ、USB二重接続、GNDA/GNDD帰路、製造時ERC/DRCの5点を重点確認するのが最も効果的である。
